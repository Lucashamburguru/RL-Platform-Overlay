# UX Review: RL Platform Overlay

**Date:** 2026-06-08
**Reviewer:** opencode (automated review)
**Scope:** Settings UI, overlay rendering, hotkey system, all HUD panels

---

## Critical Issues

### 1. No confirmation on destructive actions

Five operations permanently delete data or modify game files with no confirmation dialog:

| Action | Location | Impact |
|--------|----------|--------|
| **Reset Config** | Launch controls bar | Resets ALL settings to defaults. One misclick loses all user configuration. |
| **Alpha Boost Apply** | Boost tab | Modifies Rocket League game files. Potentially bannable (ToS violation). |
| **Alpha Boost Restore** | Boost tab | Modifies game files. Could lose custom modifications. |
| **Clear Upload Cache** | Replays tab | Deletes local Ballchasing upload cache. Must re-sync from cloud. |
| **Delete Backups** | Replays tab (Hoops Fixer) | Permanently deletes `.replay.bak` files. No undo. |

**Recommendation:** Add a confirmation modal for all five. The Alpha Boost operations should include a prominent "I understand the risks" checkbox since they violate ToS.

### 2. HUD status indicator is misleading

`settings.rs:902` — The HUD status shows "ACTIVE" (green) whenever `is_launched` is true, even if the lobby overlay is not actually visible (user hasn't pressed the HUD hotkey yet). A user who just launched the overlay sees "ACTIVE" but no overlay on screen.

**Recommendation:** Base the status on `is_visible` alone, not `is_launched`. Or show three states: "STOPPED" / "LAUNCHED (hidden)" / "VISIBLE".

## Tab Organization Issues

### 3. Overloaded Lobby tab

The "Lobby" tab bundles three unrelated concerns:
- Lobby overlay settings (theme, display mode, toggles)
- Hotkey configuration for ALL functions (not lobby-specific)
- Live preview of the lobby overlay

**Recommendation:** Move hotkeys to the Setup tab or give them their own tab. The Lobby tab should focus on lobby appearance and behavior.

### 4. Boost tab conflates two features

The "Boost" tab contains:
- Teammate Boost HUD settings (a gameplay overlay)
- Alpha Boost (Gold Rush) asset swap (a game file modification tool)

These are fundamentally different features — one is a display preference, the other modifies game files.

**Recommendation:** Rename the tab to "Boost & Alpha" or split Alpha Boost into its own tab. At minimum, add a clear visual separator between the two sections.

### 5. Setup tab has unrelated positioning controls

The "Setup" tab contains Stats API configuration alongside Overlay Positioning (drag-to-position controls and reset buttons). Positioning is a general layout concern, not specific to initial setup.

**Recommendation:** Move positioning controls to the Lobby tab (since they position the lobby overlay) or to a dedicated "Layout" section.

### 6. Duplicate "Enable Drag Position" checkbox

The drag positioning toggle appears in two places:
- Setup tab (positioning section) — `settings.rs`
- Launch controls bar — `settings.rs:911`

Both mutate the same `config_edit.layout_mode`. Having two identical controls is confusing.

**Recommendation:** Keep only the launch controls bar version, which is more accessible during use.

## Settings UX Issues

### 7. Rocket League path input duplicated

The `rocket_league_path` input field appears on:
- Setup tab
- Boost tab (Alpha Boost section)

Both edit the same config field, but seeing the same input twice creates confusion about which one is "canonical."

**Recommendation:** Show the path once on the Setup tab with a read-only reference in the Boost tab, or remove it from the Boost tab entirely.

### 8. No feedback on auto-detect failure

Both the Rocket League path and replays folder "Auto-detect" buttons silently fail when detection finds nothing. The user clicks, nothing happens, and they don't know why.

**Recommendation:** Show a brief message like "Could not detect installation. Please set the path manually." in yellow/orange after a failed detection attempt.

### 9. Transparency slider lacks context

The transparency slider ranges 0-255 with no explanation. Users don't know that 0 = fully transparent, 255 = fully opaque, or what the default (150) looks like.

**Recommendation:** Add a percentage label or descriptive text (e.g., "59% opaque") next to the slider, or use a percentage-based range (0-100%).

### 10. HUD Scale slider lacks context

The scale slider ranges 0.5-2.5 with no hint about what values mean in practice. The default is 2.2, which is quite large.

**Recommendation:** Add a label showing the current multiplier (e.g., "2.2x") or a brief note about recommended values for common resolutions.

### 11. GG Keys input has no format documentation

The "GG Keys" text input accepts a freeform string (e.g., `"T,G,G,Enter"`). There is no helper text explaining:
- That keys are comma-separated
- What valid key names are
- That the sequence is typed character-by-character

A user could type garbage and get no feedback.

**Recommendation:** Add helper text below the input: "Comma-separated key names (e.g., T,G,G,Enter). Keys are pressed in sequence."

### 12. Session overlay expanded options always visible

The three checkboxes for expanded mode ("Streaks & Stats", "Mode Breakdown", "MMR Change") are always shown, even when the display mode is set to Compact. In Compact mode, these controls have no visible effect.

**Recommendation:** Grey out or hide these options when Compact mode is selected.

### 13. Opacity slider minimum is 40, not 0

The session overlay opacity slider has a minimum of 40, not 0. Users expecting full transparency will be confused.

**Recommendation:** Either lower the minimum to 0, or add a label explaining the minimum (e.g., "Min: 40 — overlay needs some opacity to be readable").

### 14. Theme preview requires switching

The four lobby themes (Glassmorphism, High-Contrast Solid, Modern Cyber, Minimalist Floating) can only be previewed by selecting them. There are no thumbnails or descriptions beyond the names.

**Recommendation:** Add small preview thumbnails or a brief description of each theme's visual style.

## Hotkey System Issues

### 15. Modifier-only hotkey captures

`capture_egui_key` in `hotkeys.rs:154-178` captures modifier keys (Ctrl, Shift, Alt, Meta) as standalone hotkeys. If a user presses only Ctrl to "see what happens," it records "ControlLeft" as the hotkey. This is almost certainly not intentional.

**Recommendation:** Require at least one non-modifier key in the combination, or show a warning when a modifier-only key is captured.

### 16. No hotkey conflict detection

There is no check for duplicate hotkeys across the four bindings (lobby overlay, controller, settings, launch). A user could assign the same key to lobby overlay and settings panel, making one of them unreachable.

**Recommendation:** Warn when a hotkey is assigned to multiple functions.

### 17. Controller hotkey recording has no in-UI feedback

The controller hotkey recording works (captured in the input thread via `input.rs`), but the UI shows only "Listening..." with no intermediate feedback. The user presses a button and the "Listening..." label simply disappears. There's no confirmation that the correct button was captured.

**Recommendation:** Show the captured button name briefly before clearing the recording state, or flash a confirmation message.

### 18. Default hotkey choices are unusual

- `hotkey_kb: "Backspace"` — uncommon for overlay control; could interfere with text input in other apps
- `hotkey_launch: "F4"` — commonly "close tab" in browsers; potential confusion

**Recommendation:** Consider more conventional defaults (e.g., F9/F10 for overlay keys, which are less commonly used by games).

## Overlay Rendering Issues

### 19. No snap-to-grid or alignment guides

The drag-to-position system has no alignment aids. Users must eyeball panel positions across multiple displays. The three panels (lobby, boost, session) each have independent positions with no relationship enforcement.

**Recommendation:** Add optional snap-to-edge or snap-to-grid behavior. At minimum, show alignment guides when dragging near another panel's edge.

### 20. No numeric position display

During drag positioning, there's no way to see or enter precise coordinates. The position is stored as normalized coordinates (0.0-1.0), which is good for resolution independence but opaque to the user.

**Recommendation:** Show the normalized position values during drag, or add a "Position" input field for manual entry.

### 21. Position reset buttons are hard to find

The three reset buttons ("Reset Lobby", "Reset Boost", "Reset Session") are in the Setup tab's positioning section, not near the drag positioning toggle in the launch controls bar.

**Recommendation:** Move reset buttons next to the drag positioning toggle, or add per-panel reset buttons on the drag handles themselves.

## Empty State & Error State Issues

### 22. Config parse errors are silent

If `config.toml` is malformed, the app silently falls back to defaults. The error is stored in `ConfigStatus.last_error` but only shown in the Debug tab (hidden by default). The user has no idea their config was ignored.

**Recommendation:** Show a non-intrusive banner or toast when the config file fails to parse, with a "Show Details" link.

### 23. Network errors not surfaced to main UI

Stats API connection errors and parse errors are shown only in the Debug tab. A user who can't connect to the Stats API has no indication of the problem from the main UI.

**Recommendation:** Show a connection status indicator on the Setup tab or in the launch controls bar (e.g., "Not connected to Rocket League — check Stats API setup").

### 24. Boost HUD has no empty state

When no teammates are found (e.g., in a 1v1 match or free play), the teammate boost HUD simply doesn't render. There's no indication that it's working but has nothing to show.

**Recommendation:** This is acceptable behavior for an overlay. No change needed, but consider a note in the settings that the panel only appears when teammates are present.

## Accessibility Issues

### 25. No tooltips on any controls

Hovering over any setting control provides no additional information. Non-obvious controls (transparency slider, scale sliders, GG Keys input, "Show Player Stats" checkbox) would benefit from tooltips.

**Recommendation:** Add `egui::show_tooltip_text` or similar for controls where the label alone doesn't explain the behavior.

### 26. Color-only status indicators

Status colors (green/red/yellow/gray) are used without text labels in several places:
- Connection status dot in the lobby overlay header
- Upload status colors in the Replays tab
- Boost swap status in the Boost tab

Colorblind users may not be able to distinguish these.

**Recommendation:** Always pair color indicators with text labels or icons.

### 27. Small font sizes for helper text

Helper text uses 11.5px and debug labels use 12.5px. On high-DPI displays or at a distance (overlay is used while gaming), these may be hard to read.

**Recommendation:** Increase minimum font sizes for helper text to 12px and debug labels to 13px.

## Inconsistencies

### 28. config.example.toml contains legacy fields

The example config includes fields that don't exist in the `Config` struct:
- `anchor` (line 8)
- `monitor_index` (line 9) — exists in struct but unused by any UI control
- `teammate_boost_offset` (line 19)
- `teammate_boost_horizontal_offset` (line 20)
- `session_overlay_anchor` (line 32)
- `session_overlay_offset` (lines 33-36)

These are silently ignored by serde but mislead users who copy from the example.

**Recommendation:** Remove legacy fields from `config.example.toml`, or add them to the `Config` struct if they're intended for future use.

### 29. `alpha_boost_enabled` appears to be dead code

The `Config.alpha_boost_enabled` field is never read by any UI code. The Boost tab checks `inspection.game_file_state` directly.

**Recommendation:** Remove the field from the Config struct if it's truly unused, or document its purpose.

### 30. Inconsistent change detection patterns

Some controls use `if ui.control(...).changed()` while others compare against the original config value (e.g., `session_overlay_display` at `settings.rs:468-469`). This inconsistency could lead to bugs if state is modified externally.

**Recommendation:** Standardize on the `.changed()` pattern throughout.
